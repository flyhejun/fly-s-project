# 学习笔记 01 · 软件 I2C（bsp_soft_i2c.c）

> 链路位置：整条链路的最底层，STM32 与 MPU6050 之间的物理通信层。
> 学习日期：2026-08-09

## 一句话理解

用两个 GPIO 引脚（PB10/PB11）手动模拟 I2C 协议时序，把 MPU6050 的 6 轴原始数据逐位"抠"出来。它自己封装了协议，上层（mpu6050.c）只调用 `WriteByteTo` / `ReadBytesFrom` 两个接口。

---

## 1. 总线结构：开漏（open-drain）+ 上拉（最核心概念）

- 引脚**只能主动把线拉低**，不能主动拉高。
- 不驱动时（切成输入），靠**上拉电阻**把线拉回高电平。
- 任何设备一拉低，总线就是低 —— 叫"线与（wired-AND）"。
- **推论**：发完一个字节的主机必须"放手"（`SDA_Input()`），否则从机想拉低会被顶住，ACK 永远读成 1（NACK）。

**方向切换**：SCL 全程是输出（时钟永远由主机驱动）；只有 SDA 要在输出/输入间切换，因为它双向。每发 1 字节，SDA 要切两次方向（HAL_GPIO_Init 开销大，注释里已标注"后续可优化"）。

---

## 2. 时序基础

两条规则互为表里：
1. **数据有效规则**：接收方只在 SCL **高电平**期间采样 SDA，SDA 在该窗口内必须稳定。
2. 因此 SDA 在 SCL 高期间的跳变**不可能是数据**，只能是控制信号：
   - SCL 高 + SDA 高→低 = **Start**
   - SCL 高 + SDA 低→高 = **Stop**
   - 数据跳变只允许在 SCL **低电平**期间。

代码对照（Start）：
```c
SDA_HIGH(); SCL_HIGH();   // 空闲态：两线都高
SDA_LOW();                // SCL 还高 → SDA 跳变 = Start
SCL_LOW();                // 才允许进入传数据阶段
```

---

## 3. ACK / NACK：同一根线，两个方向

| 场景 | 谁驱动 | 电平含义 |
|------|--------|----------|
| 主机发完字节，等从机应答（WaitAck） | **从机**拉低 | 0 = ACK（收到了），1 = NACK |
| 主机读字节，回给从机（SendAck/Nack） | **主机**拉低/拉高 | ACK = "继续发下一字节"，NACK = "够了，别发了" |

- 回 ACK 的是**另一方**，所以发完的一方必须切输入去"听"。
- 主机读数据时：前 `len-1` 字节回 ACK，最后 1 字节回 **NACK**，然后才发 Stop。
- **真正结束通信的是 Stop，不是 NACK**；NACK 是命令从机释放总线。
- 若最后 1 字节错回 ACK → 从机继续发下一个寄存器，数据整体错位。

---

## 4. 地址与 R/W 位（易混点）

- I2C 第一字节 = 7 位地址 + 1 位 **R/W 方向位**。
- `0x68 << 1 = 0xD0`（bit0=0 → 写）；`(0x68 << 1) | 1 = 0xD1`（bit0=1 → 读）。
- **最低位是方向位，不是 ACK**。
- 同一时钟序列：8 位地址（含 R/W）是主机发的，第 9 位应答是从机回的 —— 一字节、一发、一听。
- 方向位属于"地址"，ACK 属于"应答"，是两个概念。

---

## 5. 位操作：MSB first（发 vs 收）

- **发（SendByte）**：data 是源，`data & 0x80` 取最高位发出，`data <<= 1` 顶出下一位 → 从高往低"吐"。
- **收（ReadByte）**：data 是累加器，先 `data <<= 1` 腾出 bit0，再 `data |= 0x01` 放入新位 → 从低往高"装"。
- 两者效果一致：线上都 MSB 先发/先收。"先到的 bit 要待在高位"，所以收端每收一位整体左移，新位永远进最低位。

例：收 0x96（=1001 0110），收到顺序 1,0,0,1,...：`1 → 10 → 100 → 1001 → ... → 1001 0110`。

---

## 6. DWT 周期计数延时（为什么不用 HAL_Delay）

**HAL_Delay 的 3 个问题：**
1. 精度只有 ms 级，I2C 一位要 μs 级（本项目 5μs/位）。
2. 依赖 SysTick 中断，被高优先级中断打断会拉长且不确定，破坏 I2C 位间时序。
3. 中断上下文里调用可能死等。

**DWT->CYCCNT：**
- Cortex-M 周期计数器，每 CPU 周期自增 1；80MHz 下 1 次 = 12.5ns。
- 不依赖中断，纯数周期，稳定。
- `SystemCoreClock / 1000000U` = 80 → **每微秒 80 个周期**；5μs = 400 周期。
- **减法判超时** `(CYCCNT - start) < cycles`：正确处理 32 位计数器回绕。
- 需先使能：`CoreDebug->DEMCR |= TRCENA_Msk; DWT->CTRL |= CYCCNTENA_Msk`。

## 7. 易混淆点对照表

| 概念 | 常见误解 | 正解 |
|------|----------|------|
| 地址最低位 | 表示 ACK | 是 R/W 方向位（0 写 1 读） |
| NACK | 停止通信的标志 | 命令从机"别发了"；真正结束是 Stop |
| ACK 是谁回的 | 都是主机 | 从机应答和主机应答是两种方向 |
| ReadByte 先左移 | 和 SendByte 矛盾 | 同是 MSB first，一个"吐"一个"装" |
| I2C 延时 | 用 HAL_Delay | ms 级太粗 + 中断不稳定，用 DWT 周期计数 |
